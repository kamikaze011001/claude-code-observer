# M2.2 + M2.3 — Lifecycle Workers Design

**Phase:** 2 — Rollups + retention
**Milestones:** M2.2 (session idle-timeout sweeper) + M2.3 (retention pruner)
**Date:** 2026-05-10
**Status:** Approved (pending implementation plan)

## Goal

Two periodic background workers run inside `cco serve`:

1. **Sweeper** (every 60 s) — closes `sessions` rows that have gone idle longer than `CCO_SESSION_IDLE_MIN` (default 30 min) by setting `ended_at = last_seen_at`.
2. **Pruner** (every 24 h, plus once at startup) — deletes `events` and `metric_snapshots` rows older than `CCO_RETENTION_DAYS` (default 30 days). Rollup tables are never touched.

Both workers share a single periodic-loop primitive in a new `internal/scheduler` package. Both take an injected `Clock` so tests are deterministic. Both fail-fast at startup on bad configuration; runtime errors are logged and the loop continues.

## Out of scope

- Live config reload (no SIGHUP handling)
- Per-session retention overrides
- Vacuuming the SQLite file after pruning (separate concern; not in ROADMAP gate)

## Architecture

Three new packages collaborate. The scheduler is a pure primitive; sweeper and pruner are thin workers; serve.go wires everything together.

### `internal/scheduler/` (new)

The only shared abstraction. Owns the `Clock` interface, a `Ticker` interface, a `RealClock` implementation, a `FakeClock` for tests, and a `Run` helper.

```go
type Clock interface {
    Now() time.Time
    NewTicker(d time.Duration) Ticker
}
type Ticker interface {
    C() <-chan time.Time
    Stop()
}

// Run blocks until ctx is cancelled. On every tick it calls fn(ctx).
// Errors from fn are logged with the worker name but never stop the loop.
// On exit, logs "worker stopped" once.
func Run(ctx context.Context, clock Clock, interval time.Duration, name string, log *slog.Logger, fn func(context.Context) error)
```

`FakeClock` lives in the same package (exported). It exposes `Advance(d)` and a synchronous `Tick()` so tests fire the ticker channel deterministically without sleeping.

### `internal/service/sweeper.go` (new)

```go
type Sweeper struct {
    repo  *repository.Repository
    clock scheduler.Clock
    idle  time.Duration   // default 30 * time.Minute
    log   *slog.Logger
}

func NewSweeper(repo *repository.Repository, clock scheduler.Clock, idle time.Duration, log *slog.Logger) *Sweeper
func (s *Sweeper) Tick(ctx context.Context) error
```

`Tick` computes `cutoff = clock.Now().Add(-s.idle).UnixNano()`, calls `repo.CloseIdleSessions(ctx, cutoff)`, and logs at info when N > 0, debug otherwise.

### `internal/retention/pruner.go` (new — replaces the stub)

```go
type Pruner struct {
    repo      *repository.Repository
    clock     scheduler.Clock
    retention time.Duration   // default 30 * 24 * time.Hour
    log       *slog.Logger
}

func New(repo *repository.Repository, clock scheduler.Clock, retention time.Duration, log *slog.Logger) *Pruner
func (p *Pruner) Tick(ctx context.Context) error
```

`Tick` computes `cutoff = clock.Now().Add(-p.retention).UnixNano()`, calls `repo.DeleteEventsBefore` then `repo.DeleteMetricSnapshotsBefore`. If one fails, the error is logged and the other still runs. One info line per pass: `pruner ran events_deleted=… metrics_deleted=… cutoff_ns=…`.

### `internal/repository/` (extended)

Three new methods, each in its own short transaction. No rollup tables are touched by any of them.

```go
// In sessions.go (new file)
func (r *Repository) CloseIdleSessions(ctx context.Context, cutoff int64) (int64, error)

// In retention.go (new file)
func (r *Repository) DeleteEventsBefore(ctx context.Context, cutoff int64) (int64, error)
func (r *Repository) DeleteMetricSnapshotsBefore(ctx context.Context, cutoff int64) (int64, error)
```

SQL:
- `UPDATE sessions SET ended_at = last_seen_at WHERE ended_at IS NULL AND last_seen_at < ?`
- `DELETE FROM events WHERE ts < ?`
- `DELETE FROM metric_snapshots WHERE ts < ?`

All three return `RowsAffected` for caller-side logging.

### `cmd/app/serve.go` (modified)

Adds env parsing and worker startup. Pseudocode:

```go
idleMin, err := parsePositiveIntEnv("CCO_SESSION_IDLE_MIN", 30)
if err != nil { return err }
retentionDays, err := parsePositiveIntEnv("CCO_RETENTION_DAYS", 30)
if err != nil { return err }

clock := scheduler.RealClock{}
sweeper := service.NewSweeper(repo, clock, time.Duration(idleMin)*time.Minute, logger)
pruner  := retention.New(repo, clock, time.Duration(retentionDays)*24*time.Hour, logger)

// One eager prune at startup (drops aged rows from prior runs without waiting 24h)
_ = pruner.Tick(ctx)

go scheduler.Run(ctx, clock, 60*time.Second,    "sweeper", logger, sweeper.Tick)
go scheduler.Run(ctx, clock, 24*time.Hour,      "pruner",  logger, pruner.Tick)
```

`parsePositiveIntEnv` is a small helper in `cmd/app/` (not its own package): missing → default; non-integer or ≤ 0 → return error so `serve` fails fast at startup.

## Configuration

| Env var                   | Default | Validation             | Effect                                              |
|---------------------------|---------|------------------------|-----------------------------------------------------|
| `CCO_SESSION_IDLE_MIN`    | `30`    | positive integer       | Minutes of inactivity before a session is closed    |
| `CCO_RETENTION_DAYS`      | `30`    | positive integer       | Days of raw events/metrics retained                 |

Bad values fail `cco serve` immediately with a clear error. No silent fallback to defaults — that hides operator mistakes.

## Error handling and shutdown

- **Startup:** bad env → `serve` returns an error before the receiver opens.
- **Runtime:** `scheduler.Run` logs `fn` errors with the worker name and continues. Transient SQLite contention should not crash a long-running daemon.
- **Pruner partial failure:** if `DeleteEventsBefore` fails, `DeleteMetricSnapshotsBefore` still runs. Each is logged separately.
- **Shutdown:** root `ctx` cancellation propagates to both workers via `scheduler.Run`. The receiver is stopped first (existing behavior); workers exit on the next select. We do not block waiting for them — in-flight ticks see a cancelled `ctx` and roll back via existing repo helpers.

## Logging conventions

- Sweeper: `info` only when N > 0 (`closed N idle sessions`); `debug` otherwise. Avoids 1440 daily noise lines.
- Pruner: one `info` line per tick (`pruner ran events_deleted=… metrics_deleted=… cutoff_ns=…`). Daily volume — fine to always log.
- Both workers attach `worker=<name>` via the logger passed into `scheduler.Run`.

## Testing

Coverage targets: **≥ 90% on `internal/service/sweeper.go`** and **≥ 90% on `internal/retention/`** (ROADMAP gates). `internal/scheduler/` is small but covered by its own loop test plus indirect coverage from the worker tests.

### `internal/scheduler/scheduler_test.go`

- `Run` calls `fn` once per `Tick()` of `FakeClock`.
- `Run` returns when `ctx` is cancelled.
- `Run` logs and continues when `fn` returns an error.
- `FakeClock.Advance` and `Now` round-trip correctly.

### `internal/service/sweeper_test.go` (table-driven, FakeClock + temp SQLite)

- Default 30-min threshold closes a 31-min-idle session, leaves a 29-min-idle one open.
- Custom idle (5 min) honored when passed.
- Already-closed session (`ended_at` set) untouched.
- Empty `sessions` table → no error, returns 0.
- Multiple idle sessions in one tick: all closed atomically.

### `internal/retention/pruner_test.go` (table-driven, FakeClock + temp SQLite)

- Default 30-day window: 31-day-old events deleted, today's retained.
- Custom 7-day window honored.
- `sessions` and `prompts` rows untouched after prune (rollups are forever — explicit assertion).
- Idempotent: a second `Tick` at the same clock value deletes nothing more.
- `metric_snapshots` pruned on the same cutoff.
- Empty tables → no error, returns 0/0.
- Partial failure path: simulate `DeleteEventsBefore` error (using a closed DB or similar) — `DeleteMetricSnapshotsBefore` still attempted.

### `internal/repository/sessions_test.go` and `retention_test.go`

- One test per new method exercising the SQL directly. Tight, mostly to lock the column names and the `<` boundary in.

### `cmd/app/serve_test.go`

- `parsePositiveIntEnv` table-driven: unset → default, valid → parsed, `"0"` → error, `"-1"` → error, `"abc"` → error.

## Demo (ROADMAP M2.2 + M2.3 acceptance)

**M2.2:**
- Insert two synthetic sessions: one with `last_seen_at = now`, one with `last_seen_at = now - 31 min`.
- Trigger `Sweeper.Tick` manually → only the second has `ended_at` set.
- `CCO_SESSION_IDLE_MIN=5 ./bin/cco serve` honors the override (covered by env-parsing test).

**M2.3:**
- Insert synthetic events with `ts` 31 days ago and `ts` today.
- Trigger `Pruner.Tick` → 31-day-old rows gone, today's rows retained.
- `sessions` and `prompts` rows are unchanged.
- `CCO_RETENTION_DAYS=7` retains only 7 days.
